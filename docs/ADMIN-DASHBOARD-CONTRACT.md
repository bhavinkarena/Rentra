# Admin dashboard read contract

Phase 4, 5 October 2026. Implemented locally; not deployed.

`GET /api/v1/admin/dashboard` requires the separate authenticated admin session. Inputs are `period=today|7d|30d|90d` (default `30d`) and `environment=live|test|simulated` (default `live`). Unsupported values return HTTP 400. This endpoint grants no new capability.

The response envelope contains `data.scope` and `data.modules`. Scope includes the selected period/environment, `timeZone: Asia/Kolkata`, inclusive local `from`/`to` dates, UTC `startInclusive`/`endExclusive`, today's IST date, daily dates and `generatedAt`. Periods include today's complete calendar day. Timestamp comparisons use `[startInclusive, endExclusive)`; they never depend on the database/browser's default timezone.

| Module       | Required capability       | Contents                                                                                                                                       |
| ------------ | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| applications | `admin.applications.read` | Submitted queue counts, unassigned and 48-hour SLA breakdown, oldest attention records, audit-backed decision throughput and recent events     |
| properties   | `admin.properties.read`   | Pending-review properties with a submission for the current review pass; oldest submissions                                                    |
| bookings     | `admin.records.read`      | Orders created, active visit rent, zero-filled daily series, current-state distribution of that cohort, today's unique visits, open case queue |
| finance      | `admin.payments.read`     | Verified captures, successful refund evidence, pending refund amounts, separate payment/refund exception queues                                |
| support      | `admin.support.read`      | Full unresolved queue total and actual urgent-priority count; urgent records first                                                             |
| health       | `admin.operations.read`   | Service/health/check time/staleness and open incident references; no operational payload, credentials or private evidence                      |

Unauthorized modules are absent, including counts and links. Each authorized module reads in its own repeatable-read, read-only transaction. Its counts and rows share a snapshot; modules can fail independently. A failed module returns only `{ "availability": "unavailable" }`. An available module returns `availability: available` and its data. The dashboard shows retry for failures and keeps successful modules. A zero aggregate is a valid result, never an outage fallback. Empty service observations and absent provider capture evidence are explicitly unavailable.

Every metric includes `key`, `label`, integer-string `value`, `unit` (`count` or INR `minor`), `dateBasis`, `environment`, boundaries, `generatedAt`, `filters` and its authorized frontend `href`. Money aggregates remain integer strings; no float cash arithmetic. Daily series include every local date, including zero days. Chart tables display exact values; SVG heights are presentation only.

| Metric                     | Definition                                                                                                                                                                                                                                                                                                      | Matching drill-down                                                                                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Waiting owner applications | Current `submitted` applications; unassigned and strictly older-than-48-hour counts                                                                                                                                                                                                                             | `/admin/applications` (submitted default)                                                                                                              |
| Properties awaiting review | `pending_review` with the current-pass submission                                                                                                                                                                                                                                                               | `/admin/properties?status=pending_review&submitted=1`                                                                                                  |
| Bookings created           | Orders created in the selected period/environment, including all order states; each order once                                                                                                                                                                                                                  | `/admin/bookings?createdFrom=…&createdTo=…&environment=…`                                                                                              |
| Booked rent                | Same created-order cohort. Sum visit rent excluding requested/cancelled visits and draft/held/expired/cancelled orders. Includes completed/no-show/disputed visit rent; excludes fees and deposits. This is booked rent, not captured cash or payout                                                            | Above filters plus `rentOnly=1`; rows show the matching active rent                                                                                    |
| Today's visits             | Unique non-requested/non-cancelled visits on non-draft/non-held/non-expired/non-cancelled orders. Known hours: IST start **or** end date is today. Unknown hours: stored local day is today. No interior-day occupancy count. Arrival/departure subtotals overlap; hourly and unknown-hours counts are separate | `/admin/bookings?tab=today&unit=visits&environment=…`; paginated visits, unique visit keys and original payment states                                 |
| Captured payments          | Successful real provider capture transactions whose `verified_at` is in the period/environment. A capture can relate to an order created outside the period. Missing capture evidence is unavailable; simulated facts are never provider captures                                                               | `/admin/finance/payments?environment=…&basis=capture&from=…&to=…`; captured amounts use this period, payment status remains based on lifetime evidence |
| Successful refunds         | `actual_minor` on succeeded refunds verified within the period/environment                                                                                                                                                                                                                                      | `/admin/finance/refunds?environment=…&dashboard=success&from=…&to=…`                                                                                   |
| Refunds pending            | Current expected amounts in requested/processing/unknown states; excludes failed/succeeded. Never subtracted as settled cash                                                                                                                                                                                    | `/admin/finance/refunds?environment=…&dashboard=pending`                                                                                               |
| Open cases                 | Current open booking cases across environments. No high-priority or SLA rule is invented for cases                                                                                                                                                                                                              | `/admin/booking-cases?state=open`                                                                                                                      |
| Open support               | All states except resolved, across environments. Only stored `urgent` priority creates urgency                                                                                                                                                                                                                  | `/admin/support?state=unresolved`                                                                                                                      |

Waiting-now metrics have null period boundaries and `environment: all`, except pending refunds, which follow the selected environment. Today's visit metric has today's own IST boundaries, independently of the selected analytics period. Current queues are visibly separated from period totals. Orders without explicit provenance remain `legacy_unknown`, excluded from Live/Test/Simulated analytics. Order namespace: simulated payment mode first; otherwise Test provenance or real Live provenance. Financial namespaces come from ledger environment, never summed together.

Review throughput counts approval, rejection and more-information **audit events**; one application can have multiple decisions. It is not historical queue backlog. The filtered, paginated drill-down is `/admin/applications/history?from=…&to=…`, served by `GET /api/v1/admin/applications/history` under `admin.applications.read`. Invalid/reversed dates are rejected. Recent decisions show the newest eight events in the selected period and link to this history. No audit payload or reviewer-private fields are projected.

Attention lists are bounded samples (up to eight per queue), never used to compute totals. Financial exceptions reuse payment investigation's definition and independently count uncertain/failed refunds. The same problem can appear in both queues; their combined label is queue exceptions, not unique incidents. Service observations older than two minutes are stale. Refresh retries authorized data with the URL intact. Existing application-root bookmarks still redirect to the queue.

No schema migration, chart dependency, export policy, CSV, calendar editor, provider call or money command was added. The [local query plan](evidence/admin-phase4/query-plan.json) evaluates the created-order/rent aggregate on 1,009 orders and uses the existing order/visit index. This is fixture evidence, not a production latency or capacity guarantee. Larger financial/event volumes require production query measurements before adding indexes.

Reproduce with an isolated localhost PostgreSQL server (never backend `.env`): set `PORTAL_TEST_DATABASE_URL` and optionally `ADMIN_DASHBOARD_EVIDENCE_DIR`, then run `node --import ./loader/register.mjs --test test/integration/admin-dashboard.integration.test.js`. The integration fixture drops its own database.

For browser verification, run backend `test/helpers/admin-experience-browser.mjs` with `ADMIN_DASHBOARD_FIXTURE=1`, private `ADMIN_BASELINE_FIXTURE`, `ADMIN_BASELINE_EVIDENCE_DIR`, `ADMIN_BASELINE_API_PORT=4162`, and `GATE_WEB_ORIGIN=http://127.0.0.1:3162`. Start frontend with `NEXT_PUBLIC_API_URL=http://127.0.0.1:4162/api/v1`, `RENTRA_BROWSER_FIXTURE=1`, `RENTRA_BROWSER_FIXTURE_ID=admin-phase4`, port 3162. Run `python scripts/portal-gate/admin-dashboard.py` with the same private fixture path. Optional `ADMIN_DASHBOARD_PSQL` enables the disposable health-table failure/recovery check. Send `stop` to the backend fixture terminal to drop its database; stop both local servers and remove private tokens afterward. Evidence files contain no tokens.
